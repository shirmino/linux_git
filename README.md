# CoreDataEngineers — Linux and Git Project

## Project Overview

This project was completed as part of the **CoreDataEngineers Linux and Git exercise**.

The objective is to demonstrate practical knowledge of:

* Linux
* Bash scripting
* ETL processes
* File management
* Cron scheduling
* Git
* GitHub

The project implements a Bash-based ETL pipeline that extracts data from an external source, transforms the data, and loads the resulting dataset into a Gold directory.

The project also includes a Bash script for moving CSV and JSON files between directories and demonstrates the use of Git for version control.

---

# 2. ETL Pipeline

The ETL pipeline consists of three main stages:

```text
Extract → Transform → Load
```

The pipeline is implemented in:

```text
scripts/etl.sh
```

## Extract

The Extract stage downloads the **Annual Enterprise Survey 2023 provisional CSV dataset** from Stats NZ.

The dataset URL is stored in the `DATA_URL` variable.

The downloaded CSV file is saved in:

```text
raw/
```

The resulting file is:

```text
raw/annual-enterprise-survey-2023-financial-year-provisional.csv
```

The script checks whether the download was successful before continuing with the transformation stage.

---

## Transform

The Transform stage processes the downloaded CSV file using Bash and `awk`.

Two main transformations are performed.

### Rename column

The column:

```text
Variable_code
```

is renamed to:

```text
variable_code
```

### Select columns

Only the required columns are retained:

```text
year
Value
Units
variable_code
```

The transformed dataset is saved as:

```text
Transformed/2023_year_finance.csv
```

---

## Load

The Load stage copies the transformed dataset into the Gold directory.

The final dataset is stored as:

```text
Gold/2023_year_finance.csv
```

The script confirms that the file has been successfully loaded.

The ETL script also displays messages indicating the progress of each stage:

```text
EXTRACT
TRANSFORM
LOAD
```

# 3. Cron Scheduling

The ETL pipeline is configured to run automatically using **cron**.

The scheduled execution time is:

```text
Every day at 12:00 AM
```

The cron expression is:

```text
0 0 * * *
```

The five cron fields represent:

```text
Minute Hour Day-of-Month Month Day-of-Week
```

Therefore:

```text
0 0 * * *
```

means:

```text
Every day at 00:00
```

The crontab entry is:

```bash
0 0 * * * /absolute/path/to/linux_git/scripts/etl.sh >> /absolute/path/to/linux_git/logs/etl.log 2>&1
```

The command redirects both standard output and errors to:

```text
logs/etl.log
```

## Edit crontab

```bash
crontab -e
```

## Verify the scheduled job

```bash
crontab -l
```

## Testing

For testing purposes, the job can temporarily be scheduled to run every minute:

```bash
* * * * * /absolute/path/to/linux_git/scripts/etl.sh >> /absolute/path/to/linux_git/logs/etl.log 2>&1
```

After testing, it should be changed back to:

```bash
0 0 * * * /absolute/path/to/linux_git/scripts/etl.sh >> /absolute/path/to/linux_git/logs/etl.log 2>&1
```

# 4. CSV and JSON File Management

The project includes a separate Bash script for moving CSV and JSON files:

```text
scripts/move_files.sh
```

The script moves CSV and JSON files from:

```text
json_and_CSV_old/
```

to:

```text
json_and_CSV/
```

The script supports both `.csv` and `.json` files.

It uses the project directory as its base location, allowing the script to work correctly regardless of the directory from which it is executed.

## Make the script executable

```bash
chmod +x scripts/move_files.sh
```

## Run the script

```bash
./scripts/move_files.sh
```

The script:

1. Identifies the project directory.
2. Defines the source and destination directories.
3. Checks for CSV files.
4. Checks for JSON files.
5. Moves matching files.
6. Counts the number of CSV and JSON files moved.
7. Displays a movement summary.

Example summary:

```text
=============================================================
MOVE SUMMARY
=============================================================

CSV files moved:   X
JSON files moved:  X
Total files moved: X
```

# 6. Git Ignore Configuration

Generated ETL data and log files are not intended to be stored in the GitHub repository.

The `.gitignore` file is therefore used to prevent generated files from being tracked.

The relevant configuration is:

```gitignore
# ETL generated data
raw/
Transformed/
Gold/

# ETL logs
*.log
```

This allows the ETL pipeline to continue creating files locally while preventing those generated files and logs from being pushed to GitHub.

For example, the following files remain available locally but are ignored by Git:

```text
raw/annual-enterprise-survey-2023-financial-year-provisional.csv
Transformed/2023_year_finance.csv
Gold/2023_year_finance.csv
logs/etl.log
etl.log
```

The `.gitignore` file itself is tracked because it is part of the project configuration.

# 11. Conclusion

This project demonstrates the implementation of a basic Bash-based ETL pipeline together with Linux file management, cron scheduling, and Git version control.

The ETL pipeline:

1. Extracts a CSV dataset from Stats NZ.
2. Stores the raw dataset in `raw/`.
3. Transforms the dataset using Bash and AWK.
4. Renames `Variable_code` to `variable_code`.
5. Selects the required columns.
6. Stores the transformed dataset in `Transformed/`.
7. Loads the final dataset into `Gold/`.
8. Provides automated daily execution through cron.

The project also demonstrates CSV and JSON file management through `move_files.sh`, which identifies and moves files between directories.

Git is used to maintain the project history, while `.gitignore` prevents generated datasets and log files from being tracked and pushed to the remote GitHub repository.
